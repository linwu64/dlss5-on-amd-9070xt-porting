# Production integration boundary (not applied)

The experiment proves one new export against original877e, then eight compact weights in the unchanged NativeGameFrame. It does not require changing original export semantics.

Prefer adding the ScaleOffset default4194304 and new compactw export to the existing vit-stream source/build recipe. That lets the constructor probe/cache the optional new function from the already selected module, avoiding a permanent extra whole module. The experimental sidecar is667248 file bytes; file size is not GPU residency. Its actual cold costs are already included in the resource process, and its load/setup is outside warm frame timing.

Keep a constructor-frozen availability boolean and a pointer layout tag. Only the exact byte-edge contract consumer requests the compact loader. Existing legacy cache pointer => original function; missing new export => original allocation and function; unknown shape/name/custom module selector => original route. A compact pointer must never reach any legacy hout/ordinary/split-K/fused consumer. Never retain old and compact buffers simultaneously merely to preserve a fallback. The fallback is selected before allocating a particular weight.

Compatibility matrix:

| Host / module | Weight layout / function |
|---|---|
| Old host, old or extended module | Original tail / original function |
| New host, module without compactw | Original tail / original function |
| New host, known extended module, eligible uncached weight | New tail / cached compactw |
| New host, eligible but pre-existing legacy cache | Original tail / original function |
| Unknown selector, name or shape | Original path |

Current private implementation's SHA guards bind the sidecar experiment to actual877e and14fac. A production optional-export contract should replace these experiment-specific filenames/hashes only through an explicit reviewed integration, not by accepting an arbitrary existing symbol with different tail semantics. Rebuild recipes must retain current numerical defines and eight-argument56B ABI. No new quantization, scales, kernel ordering, user configuration, game deployment or asset format is required.
