# 旧真实HDR菜单：MODE0 / MODE3 s1客观对照

这里是20261009以前记录的1296×720 HDR菜单旧帧，**不是本次游玩截图**。原GPU诊断30243只运行一次NN，保存MODE3前/后的同域结果，再用同一解码器输出两路HDR；本次仅恢复既有raw做CPU分析，没有运行游戏/GPU或改配置。五份raw的长度和SHA与历史314c573c完整相同。

查看 `comparison.png`（MODE0、MODE3、显示编码RGB有符号差分×4），以及 `crop-1-x3.png` 至 `crop-4-x3.png`（脸发、衣料、金属、暗地面，完全相同区域像素放大×3，不锐化）。所有图统一使用同一个曝光3.997892599→逐通道Reinhard→sRGB；没有分别自动曝光。它是明确约定的SDR可视化，不是用户HDR显示器的实测tone-map。差分以中灰表示零，×4后可能截断。

原始HDR的数值单位不能直接当亮度感知单位；显示编码RGB的平均变化约4.5/255，也不能一概说“看不见”。原始HDR99.68%像素发生数值变化；统一显示转换后98.33%像素的8bit值变化。像素任一通道差超过1/255约90.83%，超过4/255约44.69%；这些不是人眼JND阈值，更不是画质评分。分量分位数和每像素最大通道阈值分开统计，alpha及72行处理padding位相同。

看图后的主观观察仅限此旧场景：MODE3脸/发更暗，眉眼边缘、衣料黑白反差及局部颜色有可见变化；全图内容接近，不能据此确认生成了新细节或画质更好。它仍是同一次NN输出的残差增强，不是第二次NN推理，不能期待换一套场景内容。原始NR残差与增强后的残差幅度见stats.json，变化量不是“更接近正确答案”；这里没有NV/理想画质gold，也没有时间序列抑闪证据。

源码确有额外修正软压缩与0–1 headroom保护；本旧capture没保存逐像素内部gate/低频buffer，因此不定量声称它们吃掉了多少增益。冷单帧也不能代表当前静态warm/history或运动中的表现。复现：在repo根运行 `python3 Development/HIP/experiments/mode3-objective-20261011/analysis/compare.py /home/lmxxf/work/mode3-objective-20261011/old-menu Development/results/mode3-objective-20261011/old-menu`，raw留在外部持久目录，不入git。
